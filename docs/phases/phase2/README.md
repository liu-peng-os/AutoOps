## 前置条件（开始阶段2前必须完成）

以下三项是阶段1遗留的收口工作，**必须在第一个功能模块开发前完成**：

### 1. 鉴权收口

- [ ] 将 `github.com/dgrijalva/jwt-go` 替换为 `github.com/golang-jwt/jwt`
- [ ] 确认 token 过期时间、刷新策略、签名算法
- [ ] 确认 middleware 边界（哪些接口需要鉴权，哪些不需要）
- [ ] 补一份最小鉴权安全说明（日志脱敏、失败行为）

### 2. 日志收口

- [ ] 决定继续用 `logrus` 还是迁移到 `slog`
- [ ] 定义最小日志字段：时间、级别、request_id、user_id、模块、操作、错误
- [ ] 确认容器日志策略：stdout/stderr 优先，文件挂载只保留必要场景

### 3. 适配层接口定义

- [ ] 定义最小 Provider 接口（外部系统需要实现的方法）
- [ ] 定义同步任务生命周期：pending → running → success/failed/skipped
- [ ] 定义外部对象映射规则（外部 ID、同步状态、审计字段）

## 第一个模块的选择

从以下三个候选中选一个开始，选最小的、最确定的：

| 候选 | 外部系统 | 复杂度 | 推荐理由 |
|---|---|---|---|
| 运营工单 | 飞书多维表格 | 中 | 需求明确，飞书 API 文档完善 |
| 站点管理 | 飞书多维表格 | 中 | 和运营工单共用飞书 adapter，可复用 |
| 域名管理 | dnsmgr | 低 | 接口简单，适合第一个验证 |

**建议**：先做域名管理（最简单），验证 adapter 模式后再做飞书相关的。

---

## 第一个模块必须验证的内容

完成第一个模块后，需要确认以下问题有了答案：

1. adapter 接口设计是否合理，是否需要调整
2. 同步任务生命周期是否够用
3. 回写行为的错误处理是否完善
4. 审计日志格式是否满足需求
5. 前端列表/详情/编辑骨架是否可以复用到下一个模块

---

## 进入阶段3的标准

- 至少完成 1-2 个稳定可用的接入能力闭环
- 同步、回写、审计、错误处理机制经过真实验证
- adapter 抽象被证明可复用（至少用在两个不同的外部系统上）
- 鉴权、日志方案已正式定稿
